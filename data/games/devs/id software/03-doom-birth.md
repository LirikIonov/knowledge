## 14. DOOM: как id решила не делать Wolfenstein II { #p014 }

И id действительно ещё несколько месяцев эксплуатировала готовую формулу. Летом 1992 года почти вся команда сделала Spear of Destiny — отдельный коммерческий приквел на том же движке, с новыми уровнями, графикой, врагами и боссами. После увольнения Tom Hall в середине производства id столкнулась с довольно приземлённой проблемой.

## 18. DOOM как коллективная машина { #p018 }

DOOM особенно легко превращается в историю двух Джонов:

John Carmack
написал engine

+

John Romero
сделал levels

DOOM

Оба действительно критически важны.

Но если буквально убрать из DOOM остальных людей, получится не та игра, которую мы знаем.

Потому что финальный DOOM был уже не просто «движок + уровни». Это одновременно:

\+
gameplay code
\+

Romero спустя 25 лет именно так и описывал проект: Carmack держал основную массу кода, Adrian Carmack и Kevin Cloud — художественную часть, Petersen помогал с уровнями, Dave Taylor заполнял программные пробелы, а сам Romero писал gameplay/environment code, DoomEd и строил карты.
Rome.ro

Engine — John Carmack

Здесь никакой ревизионизм не нужен.

Технологическое ядро DOOM — в первую очередь работа John Carmack.

Он определяет фундаментальные свойства мира:

стены под произвольными углами
\+
разные высоты пола и потолка
\+
ступени
\+
движущиеся sectors
\+
variable lighting
\+
texture-mapped floors / ceilings
\+
быстрый renderer

и реализует архитектуру, которая позволяет всему этому работать на тогдашнем PC с достаточной для action-игры скоростью.

Ключевым для производительности становится использование binary space partitioning; Romero отдельно отмечает применение идей BSP Bruce Naylor как один из главных технологических скачков DOOM.
Rome.ro

То есть вклад Carmack нельзя описать:

«написал графику»

Он создаёт физические законы пространства, внутри которых вся остальная команда затем проектирует игру.

Но Carmack не писал «DOOM целиком»

Это важная граница.

Engine отвечает на вопрос:

какие пространства и игровые объекты машина способна симулировать?

Он сам по себе не отвечает:

где поставить shotgun?

сколько health дать Cacodemon?

как должен выглядеть Baron?

как сделать E1M1?

↓

превращает его в DOOM

Сам Romero описывал Carmack именно как человека, который «handled the meat of the code», но одновременно подчёркивал собственный gameplay/environment code и вклад остальных.
Rome.ro

Tools — John Romero

Вот второй слой, без которого Carmack engine крайне трудно превратить в 27 законченных уровней.

Romero пишет DoomEd.

Не очередную версию старого tile editor TED, а полноценный level editor для новой геометрии DOOM.

И это был большой отдельный программный проект.

Современная production-ретроспектива Game Developer оценивала DoomEd примерно в пять человеко-месяцев работы; id писала инструменты на NeXTSTEP, а затем пересылала и перекомпилировала игру для целевой DOS-машины.

Когда он пришёл, core first-person game уже существовал.

Его задача была сделать так, чтобы вокруг красивого игрового окна существовала полноценная законченная компьютерная игра.

Wolfenstein ещё очень легко вообразить как пару программистов, которые почти всё делают сами.

Carmack сознательно хотел дать людям возможность ковырять игры.

Причина у него была очень личная.

В подростковом возрасте он сам любил вскрывать игры — например, sector-editing Ultima II на Apple II, менять данные и смотреть, что произойдёт.

Позднее он объяснял свою позицию именно этим:

он хотел дать следующему поколению игроков то, чего сам хотел иметь подростком — возможность залезть внутрь игры значительно глубже.
