    Гейб Ньюэлл — Глава 3. Doom, Quake и создание Valve¶

    1990-е — август 1996 года. Как Doom заставил Ньюэлла усомниться в том, что главное будущее software обязательно строится внутри Microsoft; почему Quake превратил этот интерес в конкретную возможность; какую роль сыграли Michael Abrash и Mike Harrington; и как финансово независимый бывший Microsoft executive решил построить собственную компанию.

    1. Microsoft была великолепной — и именно поэтому следующий шаг выглядел безумно¶

    К середине 1990-х Гейб Ньюэлл находился в чрезвычайно комфортной позиции.

    Он провёл в Microsoft около тринадцати лет и получил огромный опыт software development, program-management опыт, понимание platform business, репутацию внутри одной из сильнейших software-компаний мира и финансовую независимость благодаря Microsoft equity.

    Уход не был спасением из разваливающейся карьеры.

    Microsoft
=
успех
+
деньги
+
статус
+
сильнейшая профессиональная среда

    Именно поэтому решение заняться videogames интересно.

    Ньюэлл должен был увидеть что-то достаточно важное, чтобы отказаться от среды, которую сам позднее называл одним из лучших мест в мире для создания software.

    Этим внешним shock стала id Software.

    2. Doom появляется в жизни Ньюэлла не как любимая игра, а как проблема Windows¶

    В начале 1990-х Microsoft пыталась превратить Windows в универсальную consumer platform, но серьёзные PC games всё ещё часто предпочитали DOS.

    Для game developer Windows могла выглядеть лишним слоем между игрой и hardware.

    Ньюэлл в то время работал с проблемами multimedia и Windows как будущей consumer platform. По его позднему рассказу, его раздражало, что game developers создавали собственные низкоуровневые решения вместо использования общего Windows layer.

    Чтобы доказать, что Windows может справляться с действительно demanding game software, нужен был максимально неудобный benchmark.

    Им стал Doom.

    если Windows
может нормально запускать Doom

↓

значит Windows
может быть серьёзной
gaming platform

    Ньюэлл связался с id Software и предложил помочь перенести Doom на Windows.

    Важно не превращать эту историю в миф:

    Ньюэлл не «написал Doom for Windows собственноручно».¶

    Конкретный engineering выполняли другие разработчики Microsoft. В позднем интервью Ньюэлл отдельно вспоминал инженера Bill McCormick и использование WinG — предшественника DirectX.

    Роль Ньюэлла была выше уровнем: выбрать Doom как стратегический proof-of-concept, договориться с id, организовать работу и использовать игру для проверки platform thesis Microsoft.

    Это один из первых моментов его карьеры, где game оказывается для него не просто entertainment product, а тестом всей computing platform.

    3. Doom оказался опасным доказательством — только не того, чего ожидала Microsoft¶

    Ньюэлл хотел использовать Doom, чтобы доказать силу Windows.

    Но сам Doom доказал ему гораздо более неприятную вещь.

    Маленькая компания в Техасе могла распространять software так эффективно, что Microsoft выглядела медленной.

    Ньюэлл позднее вспоминал внутреннее исследование Microsoft по установленному software на PC. В его пересказе Doom встречался на машинах с поразительной частотой — настолько высокой, что игра могла опережать по penetration сам Windows.

    Точные исторические числа здесь нужно воспринимать осторожно: поздние воспоминания Ньюэлла и Джона Кармака называют разные оценки, а shareware-копии Doom распространялись далеко за пределами обычной retail статистики.

    Но для биографии важнее вывод Ньюэлла:

    MICROSOFT
огромная software company
+
retail/business infrastructure

VS

id SOFTWARE
маленькая команда
+
shareware
+
networks

↓

id каким-то образом
доходит до пользователей
чрезвычайно быстро

    Ньюэлл описывал это почти как момент, когда понял:

    Microsoft недооценивает возможности Internet-era distribution.¶

    Для человека с platform background это был не просто факт про продажи Doom.

    Это был архитектурный сигнал.

    4. Doom ломает границу между «серьёзным software» и games¶

    После Doom для Ньюэлла становится всё труднее рассматривать games как несерьёзный entertainment business.

    Doom одновременно является:

    • real-time graphics software;
    • performance-critical code;
    • multiplayer/network software;
    • модифицируемой системой;
    • продуктом с необычной distribution model;
    • consumer phenomenon.

    То есть game оказывается на пересечении почти всех тем, которые уже интересовали Ньюэлла в Microsoft.

    graphics
+
networking
+
real-time response
+
tools
+
community
+
distribution

    Поэтому его интерес к games нельзя сводить к:

    Гейб любил играть и решил делать игры.

    Он действительно любил games.

    Но стратегически его зацепило другое:

    games оказались одним из мест, где software industry быстрее всего сталкивалась с будущими проблемами.¶

    5. Doom и Internet дают первый большой анти-Microsoft сигнал¶

    Microsoft дала Ньюэллу belief в platform leverage.

    Теперь id показывает другой вид leverage.

    small developer
↓
network/shareware
↓
users сами распространяют software
↓
community растёт

    Именно здесь начинает формироваться вопрос, который позже станет фундаментальным для Steam:

    если software состоит из bits

↓

почему путь этих bits
к пользователю
должен определяться
физической коробкой,
retail shelf
и огромной цепочкой посредников?

    Steam появится намного позже.

    Никакого готового Steam-плана у Ньюэлла в 1993 году нет.

    Но Doom уже показывает ему:

    distribution тоже является software problem.¶

    6. Ньюэлл не ушёл из Microsoft сразу после Doom¶

    Doom вышел в 1993 году.

    Valve появилась только в 1996-м.

    Ньюэлл ещё несколько лет продолжал работать в Microsoft.

    Это важно, потому что решение вызревало постепенно.

    Doom был сильным evidence:

    маленькая game company
может делать удивительные вещи

    Но чтобы бросить первую карьеру и вложить миллионы собственных денег, одной интересной игры недостаточно.

    Ньюэллу нужны были технологический foundation, партнёр, доверенный мост в game industry и понимание, что новая компания вообще способна начать работу без нескольких лет infrastructure development.

    Эти элементы сложились вокруг Quake.

    7. Michael Abrash — человек между двумя мирами¶

    Michael Abrash уже был знаменитым low-level programmer и technical writer. Ньюэлл знал его ещё по Microsoft.

    Для Джона Кармака Abrash был одним из programming heroes.

    В итоге получилась необычная траектория:

    MICROSOFT
↓
Michael Abrash
↓
id Software
↓
Quake

    Кармак убедил Абраша перейти в id и работать над Quake technology.

    Для Ньюэлла это имело огромное значение.

    id больше не была просто внешней компанией, которая сделала Doom.

    Внутри неё находился человек, которого Ньюэлл знал, чьё техническое мнение чрезвычайно уважал и который понимал одновременно культуру Microsoft и культуру id.

    Абраш стал мостом доверия.

    8. «Quake будет худшей игрой на Quake engine»¶

    Ньюэлл позднее вспоминал фразу Абраша:

    Quake will be the worst game done on the Quake engine.

    Смысл не в оскорблении Quake.

    Абраш настолько верил в технологию, что считал: первая игра покажет только часть того, что foundation позволяет сделать.

    Для Ньюэлла это идеальный argument.

    Microsoft уже научила его мыслить platform layers.

    Теперь id создаёт game technology, которая сама может стать layer для чужих products.

    QUAKE ENGINE
↓
не одна game

а
foundation
для множества games

    Это резко снижает barrier для новой студии.

    Ньюэллу не нужно сначала доказать:

    мы способны написать renderer лучше Кармака.

    Можно взять уже сильную технологическую основу и потратить время на другую проблему:

    какую game поверх неё мы способны сделать?

    9. Анти-NIH принцип появляется раньше самой Valve¶

    Для группы бывших Microsoft engineers был очень соблазнительный путь:

    мы технические люди
↓
напишем собственный engine
↓
покажем,
что умеем лучше всех

    Ньюэлл и Харрингтон делают противоположное.

    Carmack + Abrash
уже решили
огромный класс сложных problems

↓

лицензируем technology

↓

свою innovation
делаем поверх неё

    Этот выбор раскрывает будущий стиль Ньюэлла.

    У него нет особой ценности в формуле:

    всё важное обязаны придумать лично мы.

    Его вопрос другой:

    что сейчас является лучшим available layer для нашей задачи?¶

    10. Mike Harrington — второй человек, без которого Valve не появляется¶

    Миф GabeN плохо влияет на раннюю историю Valve.

    Реально компания начинается как партнёрство двух людей:

    • Gabe Newell;
    • Mike Harrington.

    Харрингтон тоже был Microsoft veteran и значительно более hands-on technical человеком в ранней Valve.

    По поздним воспоминаниям Monica Harrington, именно Mike всё серьёзнее думал о создании game company, когда его Microsoft-проект был закрыт и он оказался в фазе переоценки следующего шага.

    В какой-то момент Harrington и Newell обнаружили, что думают об одном и том же:

    уйти из Microsoft
+
создать game company

    И решили делать это вместе.

    11. Почему пара Newell–Harrington работала¶

    По поздним описаниям ранней Valve их различие выглядело примерно так.

    Gabe Newell¶

    Сильнее тяготел к:

    • product direction;
    • большой картине;
    • расширению scope;
    • strategic bets;
    • business/platform logic.

    Mike Harrington¶

    Сильнее тяготел к:

    • hands-on programming;
    • practical implementation;
    • development management;
    • production reality;
    • завершению продукта.

    Geoff Keighley позднее описывал их почти архетипично:

    Gabe
=
ambitious dreamer

Mike
=
practical realist
who liked to ship product

    Формула упрощает реальных людей, но для понимания ранней системы власти полезна.

    Valve начинается как 50/50 partnership, где рядом с Ньюэллом существует человек сопоставимого юридического и финансового веса.

    Позднее такого человека рядом уже не будет.

    12. Abrash связывает Harrington/Newell с id¶

    Связи Harrington с Abrash были особенно полезны.

    По позднему рассказу Monica Harrington, Mike когда-то помогал обучать Abrash внутри Microsoft. Теперь этот relationship неожиданно возвращал value.

    Abrash уже работал над Quake и мог снизить trust barrier между id и двумя бывшими Microsoft employees без game-industry track record.

    На бумаге pitch мог звучать почти нелепо:

    два обеспеченных человека
из Microsoft
↓
хотят создать game studio
↓
просят одну из лучших
3D technologies мира

    Личная техническая репутация и связи превращали это из фантазии в реальный разговор.

    13. Поездка в Техас — момент, когда идея становится проектом¶

    Ньюэлл позднее вспоминал поездку к id Software очень просто.

    Он, Mike Harrington и несколько будущих участников Valve отправились в Техас.

    Там они поговорили с людьми id.

    И уехали с Quake source code и ощущением, что теперь действительно создают game company.

    В интервью Washington Post Ньюэлл почти комично сокращал весь переход:

    мы знали guys at id
↓
поехали поговорили
↓
они дали Quake source
↓
ну значит,
видимо,
создаём game company

    Реальные legal/business детали лицензии сложнее этой истории.

    Но психологически она важна.

    До поездки:

    идея

    После:

    technology
+
relationship
+
реальный production path

    Valve перестаёт быть разговором бывших Microsoft сотрудников.

    14. John Carmack и John Romero — два разных вида влияния id¶

    id Software влияла на Ньюэлла не только через engine как кусок кода.

    John Carmack¶

    Для Ньюэлла Кармак был proof того, какой leverage способен иметь выдающийся engineer.

    Это прекрасно совпадало с Microsoft-наблюдением Ньюэлла:

    talent
не является
линейно взаимозаменяемым

    John Romero¶

    Romero представлял другую сторону id:

    • game-development culture;
    • design;
    • community;
    • developer relations;
    • энергию вокруг games как продукта.

    Во время ранних контактов id помогала новичкам из Microsoft понять, что game studio — это не просто обычная software company с другими executable files.

    Ньюэлл и Харрингтон были опытными software people.

    Но в games они всё равно оставались новичками.

    15. Doom и Quake научили Ньюэлла разным вещам¶

    Полезно разделять.

    Doom¶

    DISTRIBUTION
+
COMMUNITY
+
small-team leverage

    Doom показал, что network-driven software business может двигаться иначе, чем traditional corporate distribution.

    Quake¶

    TECHNOLOGY
+
ENGINE AS PLATFORM
+
MODDABILITY

    Quake показал reusable technological foundation, поверх которого можно строить чужие products.

    Условно:

    DOOM
↓
как software
может распространяться

QUAKE
↓
как software
может становиться foundation
для другого software

    Между этими двумя уроками и рождается большая часть будущего мышления Valve.

    16. Почему games оказались идеальной лабораторией¶

    Если Ньюэлл хотел проверить, действительно ли маленькая post-Microsoft company может работать лучше, чем большая corporation, games были почти идеальным experiment.

    real-time graphics
+
simulation
+
AI
+
networking
+
tools
+
human interaction
+
community
+
digital distribution

    И ещё один важный фактор:

    результат очень быстро становится виден пользователю.¶

    Software может быть технически блестящим и при этом скучным.

    Game мгновенно наказывает за это.

    Для человека, который начинает всё сильнее ценить feedback loops, это очень привлекательная среда.

    17. Уход из Microsoft — не бунт¶

    Ньюэлл покинул Microsoft в 1996 году.

    Ему было около тридцати трёх.

    Это важно формулировать правильно:

    НЕ:
ненавижу Microsoft,
ухожу строить её противоположность

А:
Microsoft была отличной школой,
но следующая интересная problem
теперь находится снаружи

    Никакого публичного разрыва с Gates или Ballmer не было.

    Ньюэлл продолжал высоко оценивать раннюю Microsoft.

    В недавнем интервью он описал решение выражением:

    put my money where my mouth was

    То есть если он действительно считал, что Microsoft упускает новую internet/software model, пора было не убеждать корпорацию бесконечно, а поставить на собственную гипотезу собственные деньги.

    18. Финансовая свобода превращает мнение в проверяемую гипотезу¶

    Microsoft equity дала Ньюэллу возможность:

    • уйти без нового работодателя;
    • финансировать startup;
    • несколько лет платить разработчикам;
    • пережить отсутствие немедленной прибыли;
    • не отдавать control венчурному фонду.

    Его убеждение:

    маленькая команда
+
сеть
+
software craft
может работать иначе

    перестаёт быть философией.

    Теперь это дорогой experiment, который Ньюэлл оплачивает лично.

    Microsoft сама, через созданное ею богатство ранних сотрудников, фактически финансирует компанию, созданную для проверки идей, которые Ньюэлл уже не хотел проверять внутри Microsoft.

    19. Newell и Harrington создают не только game studio¶

    При основании компании было две задачи.

    Первая:

    сделать хорошую PC game

    Вторая:

    проверить,
можно ли построить
software company иначе

    Microsoft дала им положительную и отрицательную модель одновременно.

    Они знали, насколько мощной бывает маленькая high-talent organization, и видели, насколько много management/process появляется после роста.

    Поэтому новая компания должна была стать экспериментом:

    можно ли сохранить
talent density
+
быстрый feedback
+
техническую автономию

и не обрасти
лишними слоями?

    Радикально flat Valve из handbook 2012 года ещё не существует.

    Но вопрос уже существует.

    20. 24 августа 1996 года — Valve и свадьба в один день¶

    24 августа 1996 года юридически оформляется Valve.

    Valve Handbook позднее отдельно зафиксирует деталь:

    formation papers are signed on the same day as Gabe’s wedding.

    То есть один день объединяет:

    брак
+
основание компании

    Публичные биографические источники называют женой Ньюэлла Lisa Mennet; семейную историю разумнее подробно разбирать в отдельной личной главе.

    Здесь важен сам контраст.

    1996 год для Ньюэлла — реальный biographical break:

    • закончена Microsoft era;
    • появляется собственная компания;
    • начинается новая семья;
    • меняется индустрия;
    • появляется личная финансовая ставка.

    21. Почему название Valve¶

    Newell и Harrington рассматривали странные варианты вроде:

    • Hollow Box;
    • Fruitfly Ensemble;
    • Rhino Scar.

    В итоге выбрали Valve.

    Ньюэлл позднее объяснял, что не хотел названия в типичном стиле macho/edgy game studios девяностых.

    Valve звучит технически, коротко и нейтрально.

    В ретроспективе слово почти идеально подходит компании, которая позже будет управлять потоками software, content и пользователей.

    Но превращать это в сознательную метафору Steam было бы уже красивой фантазией.

    В 1996 это просто название новой game company.

    22. Компания появляется рядом с Microsoft — физически и психологически¶

    Valve основывается в Kirkland, Washington, недалеко от Microsoft.

    Ньюэлл остаётся внутри того же регионального talent ecosystem.

    У него рядом:

    • бывшие коллеги;
    • engineers;
    • Microsoft veterans;
    • знакомые technical people.

    Поэтому ранняя Valve во многом строится как гибрид:

    Microsoft craft knowledge
+
id technology
+
собственный capital
+
новые game-development people

    Компания не рождается из ничего.

    Она собирает несколько сильных миров в одной точке.

    23. Mike и Gabe ещё не умеют делать games — и прекрасно это понимают¶

    У Ньюэлла и Харрингтона есть огромный software experience.

    Но game development требует disciplines, которых у founders нет:

    • level design;
    • animation;
    • art;
    • narrative;
    • encounter design;
    • pacing;
    • sound;
    • player psychology.

    Поэтому одна из самых умных вещей ранней Valve — не притворяться, будто founders обязаны лично быть лучшими во всех областях.

    Они начинают искать людей с реальной работой.

    Это раннее проявление будущего Ньюэлла:

    его сильнейшая роль — не обязательно самому быть лучшим specialist, а найти человека, который знает конкретную область намного лучше него.¶

    Monica Harrington позднее точно описывала эту сторону Ньюэлла: ему нравилось видеть людей в команде, которые были реально хороши в том, что делают.

    24. Найм как охота за доказанным talent¶

    В 1996:

    Valve games shipped = 0

    Поэтому founders активно ищут людей по интересной работе, а не только по стандартному résumé.

    Среди ранних историй найма появляются:

    • Microsoft veterans;
    • designers из enthusiast/community среды;
    • tool developers;
    • люди с нетипичной карьерой;
    • международные hires.

    Valve Handbook позднее отметит, что уже в 1996 компания нанимала целые game teams и первого сотрудника из Великобритании.

    Именно здесь начинает проявляться Newell hiring philosophy:

    НЕ:
какая у тебя правильная карьерная лестница?

А:
что интересного ты уже сделал?

    Позже Team Fortress, Counter-Strike и Portal превратят эту модель в легенду.

    Но начинается она до Half-Life.

    25. Monica Harrington — важная фигура, которую ранняя легенда Valve почти стерла¶

    Ранняя история Valve обычно сводится к двум founders:

    Gabe Newell
+
Mike Harrington

    Юридически это правильно.

    Но для реальной истории компании этого недостаточно.

    Monica Harrington, тогда жена Майка и опытный Microsoft marketing executive, была важной частью founding environment.

    Сначала она оставалась сотрудницей Microsoft и помогала Valve неформально.

    Позднее присоединилась к компании full-time и стала её первым крупным marketing/business leader.

    Её поздние воспоминания добавляют важную коррекцию к легенде о двух технических мужчинах, которые просто сделали Half-Life.

    В startup одновременно строились:

    GAME
+
TEAM
+
PUBLISHER RELATIONSHIP
+
MARKETING
+
BUSINESS MODEL

    И не все эти слои строил Ньюэлл.

    Это важно именно для биографии Гейба:

    его сила проявляется внутри группы сильных людей, а не вместо них.¶

    26. Первая идея Valve была менее героической, чем Half-Life¶

    Сегодня кажется естественным:

    Valve основана
↓
сразу хочет
сделать masterpiece

    Поздние воспоминания Monica и Mike Harrington показывают более прагматичный ранний вариант.

    У founders существовала идея сначала сделать условный B-title:

    не слишком амбициозную game
↓
собрать team
↓
научиться production
↓
следующую сделать великой

    С точки зрения engineering learning это звучит разумно.

    С точки зрения game business — потенциально смертельно.

    Monica Harrington вспоминала, что провела business analysis и пришла к жёсткому выводу:

    посредственная первая game
↓
не создаёт studio foundation
↓
она просто исчезает
с retail shelf
↓
компания умирает

    То есть культовый maximalism Valve не обязательно существовал в полностью сформированном виде в момент регистрации компании.

    Он усиливается уже внутри реального business pressure.

    27. Рынок игр 1990-х был намного жестче, чем кажется после Steam¶

    Сегодня developer способен годами продавать старую game через digital store.

    В 1996 physical retail работал иначе.

    Shelf space ограничено.

    Тысячи releases конкурируют за внимание.

    Большинство исчезает практически незаметно.

    Для новой студии первая игра может быть:

    успех
или
смерть компании

    Именно поэтому решение Valve постепенно смещается от:

    сделаем учебный B-title

    к:

    первая game
обязана дать
реальную причину
обратить на нас внимание

    Это важный background будущего решения 1997 года не выпускать слабую Half-Life.

    Сам кризис Half-Life относится уже к следующей главе.

    28. Sierra — независимость ещё очень неполная¶

    У Ньюэлла и Харрингтона есть собственные деньги.

    Есть Quake technology.

    Есть команда.

    Но всё ещё нет собственного пути к массовому покупателю.

    В 1996 physical game business требует publisher.

    Valve заключает сделку с Sierra On-Line.

    Sierra даёт:

    • publishing expertise;
    • retail distribution;
    • marketing reach;
    • advance;
    • доступ к commercial infrastructure.

    То есть Valve с первого дня независима далеко не полностью.

    DEVELOPMENT
↓
Valve

DISTRIBUTION / RETAIL
↓
внешний publisher

    Ньюэлл пока принимает эту dependency.

    Позже отношения с publisher станут одним из источников его obsession с самостоятельным control distribution.

    Но в 1996 строить Steam вместо первой игры было бы бессмысленно.

    Нужно пользоваться существующим layer.

    Это тоже характерно для Ньюэлла:

    dependency не обязательно устранять немедленно.¶

    Сначала она должна реально стать bottleneck.

    29. Quiver и Prospero — Valve ещё не знает собственной identity¶

    После основания Valve начинает сразу несколько направлений.

    Quiver¶

    Проект, который постепенно превратится в Half-Life.

    Название связывали с атмосферой рассказа Stephen King The Mist — обычные люди оказываются внутри внезапного научно-фантастического кошмара.

    Prospero¶

    Более adventure/narrative-oriented project.

    Для биографии Ньюэлла важна не конкретная mechanics этих игр.

    Важен факт:

    Valve не была основана с уже найденной Half-Life formula.¶

    Компания реально искала собственную identity.

    несколько projects
↓
несколько design directions
↓
prototype
↓
смотрим,
где появляется настоящая value

    Это ранняя версия поведения, которое потом станет для Valve почти нормой.

    30. Quake engine — здесь достаточно понимать одно¶

    Историю GoldSrc, QuakeWorld и техническую эволюцию Half-Life нужно подробно хранить в отдельных исследованиях Half-Life / Source / id Tech.

    Для биографии Ньюэлла достаточно следующего.

    Valve лицензирует Quake technology.

    Затем команда начинает очень глубоко её модифицировать под собственные задачи.

    не строить
foundation заново

↓

взять сильный доступный layer

↓

переписать там,
где design требует
другого поведения

    Это и есть биографически важный принцип.

    Точный процент переписанного исходного кода здесь вторичен.

    31. Что Ньюэлл реально принёс в раннюю Valve¶

    Он пришёл не как великий game designer.

    Не как лучший 3D programmer.

    Не как writer.

    Не как level designer.

    Его initial contribution лучше описывать так.

    Capital¶

    Он способен финансировать риск.

    Software craft¶

    Он понимает, как строятся сложные software projects.

    Product judgement¶

    Он привык спрашивать, зачем feature существует для пользователя.

    Platform thinking¶

    Он видит engines, tools и distribution как strategic layers.

    Hiring instinct¶

    Он чрезвычайно серьёзно относится к поиску сильных людей.

    Willingness to abandon conventional path¶

    У него нет сакральной привязанности к Harvard, Microsoft или стандартной corporate career, если новая среда кажется более интересной.

    Именно этот набор, а не auteur genius, становится главным вкладом Ньюэлла в первую Valve.

    32. Что Harrington приносит в эту систему¶

    Mike Harrington закрывает реальные слабые стороны раннего Gabe.

    Он:

    • ближе к code;
    • ближе к day-to-day implementation;
    • лучше чувствует production practicality;
    • является равным co-owner;
    • способен спорить с Newell без status asymmetry.

    Это особенно важно.

    Позднее у Ньюэлла будут чрезвычайно сильные коллеги.

    Но равного co-founder/owner рядом уже не будет.

    В 1996 он существует.

    Поэтому раннюю Valve правильнее представлять:

    NEWELL
↔
HARRINGTON

    а не:

    NEWELL
↓
все остальные

    33. Два founders используют финансовую свободу одинаково — пока¶

    И Newell, и Harrington пришли из Microsoft с деньгами.

    В 1996 это позволяет обоим сделать один и тот же выбор:

    не брать следующую
безопасную corporate job

↓

создать company

    Позднее их отношение к той же свободе радикально разойдётся.

    Harrington после Half-Life решит, что уже доказал себе главное и хочет другой жизни.

    Newell увидит успех как разрешение делать ещё более крупные ставки.

    В 1996 этой развилки ещё нет.

    Они находятся на одной стороне эксперимента.

    34. Valve как проверка сразу двух гипотез¶

    При основании компании Ньюэлл проверяет не одну идею.

    Гипотеза 1. Games¶

    можем ли мы
сделать выдающуюся game,
если умеем хорошо
строить software?

    Гипотеза 2. Company¶

    можем ли мы
построить organization,
которая сохраняет
свойства ранней Microsoft,
но не повторяет
её рост в bureaucracy?

    Именно поэтому Valve всегда будет странно балансировать между двумя identity:

    GAME DEVELOPER

и

SOFTWARE / ORGANIZATIONAL LAB

    Первая Half-Life проверит обе гипотезы одновременно.

    35. Главный интеллектуальный переход этой главы¶

    До Doom основной мир Ньюэлла:

    великие software systems
строятся внутри
великих software companies

    После id:

    маленькая команда
может:

создать frontier technology
+
распространить её по сети
+
собрать community
+
изменить ожидания пользователей

    Microsoft научила Ньюэлла масштабу platform.

    id научила:

    размер организации и размер влияния не обязаны совпадать.¶

    Из объединения этих двух идей и рождается будущая Valve.

    36. Почему уход всё-таки был настоящим риском¶

    Легко обесценить ставку Ньюэлла:

    он был богат
↓
какой риск?

    Финансовая подушка действительно была огромным преимуществом.

    Но риск не исчезал.

    Он покидал успешную карьеру, одну из самых быстрорастущих tech companies мира, среду с reputation/network и понятный professional path.

    И шёл в industry, где у него нет shipped game, большинство новых studios исчезает, publisher power огромна, retail shelf life короткая, а production discipline отличается от business software.

    Правильнее:

    финансовый риск
сильно уменьшен

НО

professional / reputational / strategic risk
остаётся огромным

    37. Первый настоящий пример «спуститься на слой ниже»¶

    В общей биографии Ньюэлла часто появляется pattern:

    текущая problem
↓
обнаружить underlying layer
↓
работать уже с ним

    Здесь он проявляется впервые очень явно.

    Исходный вопрос:

    как сделать интересную game?

    Но Newell/Harrington сначала решают:

    какой engine layer
даст нам лучший старт?

    Ответ:

    Quake technology

    Позже тот же способ мышления появится в Steam, Linux, hardware, VR и BCI.

    В 1996 масштабы меньше.

    Форма уже узнаваема.

    38. Microsoft дала уверенность; id дала разрешение¶

    Хорошая короткая формула перехода:

    Microsoft¶

    мы умеем
делать software

    id Software¶

    small game company
может быть
technological frontier

    Quake¶

    готовый foundation,
чтобы начать
прямо сейчас

    Microsoft equity¶

    деньги,
чтобы позволить себе
ошибиться

    Mike Harrington¶

    равный партнёр,
с которым риск

    Только сочетание всех факторов объясняет Valve лучше простой истории:

    Гейб любил Doom и решил делать игры.

    39. К августу 1996 ещё ничего не доказано¶

    Сегодня слово Valve автоматически вызывает:

    Half-Life
Steam
Portal
Counter-Strike
Dota
Steam Deck

    24 августа 1996 года нет ничего из этого.

    Есть:

    • два бывших Microsoft сотрудника;
    • деньги;
    • Quake license;
    • новая компания;
    • несколько hires;
    • высокая уверенность в software craft;
    • почти нулевой shipped-game track record.

    Valve вполне могла стать ещё одной из тысяч game studios девяностых, о которых сегодня никто не помнит.

    Следующий период решит, была ли теория Ньюэлла о маленькой сильной software company реальной или красивой самооценкой бывшего Microsoft millionaire.

    Итог главы¶

    Главная причинная цепочка:

    MICROSOFT
↓
platform thinking

DOOM
↓
network distribution
+
small-team leverage

MICHAEL ABRASH
↓
bridge to id

QUAKE
↓
reusable technological foundation

MIKE HARRINGTON
↓
equal co-founder
+
production counterweight

MICROSOFT EQUITY
↓
financial optionality

↓

VALVE

    Valve родилась не из ненависти Ньюэлла к Microsoft.

    Она родилась из сочетания лучших уроков Microsoft с доказательством id Software, что маленькая команда может двигаться быстрее и создавать более интересное computing будущее.

    Ньюэлл решил проверить это собственными деньгами.

    24 августа 1996 года experiment начался.

    Но пока это всё ещё только experiment.

    Настоящая проверка наступит, когда выяснится, что первая Half-Life — технологически впечатляющая, дорогая и при этом недостаточно хорошая игра.

    Переход к следующей главе¶

    DOOM
↓
QUAKE
↓
ABRASH
↓
NEWELL + HARRINGTON
↓
VALVE
↓
QUAKE ENGINE
↓
QUIVER / PROSPERO
↓

HALF-LIFE

    Следующая глава — Half-Life: первая большая проверка Ньюэлла.

    Там фокус будет не на полной истории разработки Half-Life, потому что для неё существует отдельное исследование, а на вопросах:

    • какую роль Ньюэлл реально играл;
    • каким руководителем он был;
    • почему playtesting стал для него центральным инструментом;
    • почему в 1997 году он согласился не выпускать практически готовый продукт;
    • как успех Half-Life закрепил его максимализм;
    • что он понял из mod-community;

    Фактологические оговорки¶

    «Doom был установлен на большем числе PC, чем Windows»¶

    Это известное воспоминание Newell/Carmack о Microsoft survey, а не идеально реконструированная современная статистика. В тексте оно используется как событие, повлиявшее на мышление Ньюэлла, а не как абсолютно точная оценка installed base.

    «Quake будет худшей игрой на Quake engine»¶

    Фраза известна из позднего рассказа Ньюэлла о Michael Abrash. Ньюэлл сам оговаривал, что вспоминает её приблизительно.

    Quake → GoldSrc¶

    Техническая родословная намеренно не разворачивается. Она относится к отдельным исследованиям id Tech / Half-Life / Source. Для биографии Ньюэлла важен decision: лицензировать сильный внешний foundation и строить отличие поверх него.

    Кто «основал Valve»¶

    Юридические founders — Gabe Newell и Mike Harrington. Monica Harrington не была legal co-founder в документах, но её поздние свидетельства и работа показывают существенную роль в business/marketing foundation ранней компании.

    Свадьба Ньюэлла¶

    Valve Handbook надёжно подтверждает, что formation papers были подписаны в день свадьбы Ньюэлла. Подробности семейной биографии будут вынесены в отдельную личную главу.
