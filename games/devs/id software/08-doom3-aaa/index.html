    43. Возвращение к Doom после Quake III: когда Carmack фактически выбрал следующую игру компании¶

    После Quake III Arena id оказалась в очень странной точке.

    С одной стороны, компания только что довела собственную философию конца девяностых почти до предела:

    Quake III

    =

    multiplayer + movement + weapons + networking + renderer + mods + PC hardware

    С другой — внутри id уже назревало желание сделать почти противоположную игру:

    single-player

    dark atmosphere

    monsters

    horror

    scripted experience

    DOOM

    И решение вернуться к Doom не было спокойным:

    «ну мы давно не делали Doom, давайте теперь Doom»

    Наоборот.

    Компания уже начала готовить другой проект.

    Два совладельца, Kevin Cloud и Adrian Carmack, были против нового Doom.

    А John Carmack в итоге фактически сказал им:

    либо следующая игра — Doom, либо увольняйте нас.

    И владельцы, формально контролировавшие больше половины компании, уступили. Сам Carmack публично описал эту внутреннюю войну 1 июня 2000 года. GitHub +1

    Изначально идея нового Doom уже давно ходила по офису

    После завершения Quake III Arena в декабре 1999 года вопрос был:

    ЧТО ДАЛЬШЕ?

    И Doom был одним из очевидных кандидатов.

    По словам Carmack, одно только обсуждение возможности снова сделать Doom вызывало у большинства сотрудников почти физически ощутимый энтузиазм.

    Его формулировка:

    обсуждение нового Doom приносило “almost palpable thrill” большинству команды. GitHub

    Это важно.

    Не:

    Carmack один захотел Doom

    ↓

    заставил всех

    Наоборот:

    многие сотрудники: DOOM — ДА

    Главное сопротивление шло именно со стороны части ownership.

    Особенно против был Adrian Carmack

    John в своей .plan написал совершенно прямо:

    Adrian настолько сильно не любил эту идею, что предложение нового Doom раз за разом отклонялось. GitHub

    И его позицию можно вполне понять.

    Посмотрим, чем id занималась с 1991-го:

    Keen

    Wolfenstein

    Doom

    Doom II

    Quake

    Quake II

    Quake III

    У компании только что появилась возможность сказать:

    хватит доить старые бренды, давайте сделаем что-то совершенно новое.

    Именно так поздние источники описывают сопротивление Adrian и Kevin: они опасались, что id слишком часто возвращается к старым формулам и собственным старым IP. GameSpot +1

    То есть позиция была не:

    DOOM — плохая игра

    а:

    ID SOFTWARE не должна навсегда стать:

    DOOM QUAKE WOLFENSTEIN по кругу

    Очень разумный стратегический вопрос, особенно для компании, которая когда-то после Wolfenstein сознательно выбрала новый IP Doom, а после Doom — новый IP Quake.

    И id реально начала делать другую игру

    Это важная деталь, потому что Doom не просто победил на brainstorming.

    Carmack написал:

    design work on an alternate game has been going on...

    То есть альтернативный проект уже находился в preproduction параллельно с:

    Quake III: Team Arena

    +

    Carmack R&D

    GitHub

    Graeme Devine позднее назвал этот проект:

    QUEST

    И вспоминал, что команда уже делала:

    concept art;

    game-design brainstorming;

    технологические обсуждения;

    ранний preproduction.

    По его словам, отмена Quest ради Doom 3 стала для него одним из самых болезненных конфликтов с Carmack и фактически началом его собственного отдаления от id. Shacknews

    То есть:

    DOOM

    победил не пустоту.

    Он убил другой уже начинавшийся проект.

    Quest при этом была как раз попыткой выйти из старой колеи

    Поздние описания проекта характеризовали её как куда более необычную для id вещь — multiplayer/RPG-ish концепцию с более сложным миром, а не просто очередной прямолинейный FPS. GameStar

    Здесь лучше не переоценивать подробности — проект умер очень рано и его design не успел зафиксироваться окончательно.

    Но направление понятно:

    POST-QUAKE III ID могла пойти:

    НЕ Doom НЕ Quake НЕ Wolfenstein

    и попытаться снова создать:

    NEW IP + NEW TYPE OF GAME

    Практически вернуться к духу:

    после Wolfenstein → Doom

    после Doom → Quake

    Это был реальный альтернативный путь компании.

    И вот здесь история снова становится похожа на original Quake — только роли перевёрнуты

    В 1995 году:

    Romero: давайте рискнём и найдём новый type of game

    Carmack: хватит, делаем понятный shooter

    В 2000-м:

    часть leadership: давайте пойдём в новую IP / Quest

    Carmack: НЕТ

    делаем DOOM

    То есть человек, который когда-то отрезал экспериментальный original Quake ради shipping, теперь снова выбирает более определённую игровую идентичность.

    Но на этот раз ставки ещё выше:

    не просто game design decision

    а

    КАКОЙ PROJECT делает вся компания следующие годы Почему идея Quest начала разваливаться

    Carmack сам перечислил несколько факторов.

    1. Внутри команды не было энтузиазма

    Он пишет:

    general lack of enthusiasm for the proposed plan

    То есть проект мог существовать на бумаге.

    Но команда не горела им. GitHub

    Для маленькой id это огромная проблема.

    Помним её модель:

    не 300 сотрудников

    а

    маленькая elite team

    Если половина этих людей думает:

    «ну ладно, сделаем»

    а не:

    «БЛЯТЬ, Я ХОЧУ ЭТО ДЕЛАТЬ»

    ты теряешь огромную часть преимущества маленькой компании.

    1. Return to Castle Wolfenstein неожиданно показал, что старый IP может ощущаться новым

    И вот здесь огромную роль сыграла E3 2000.

    Return to Castle Wolfenstein делала не основная id-команда — это был внешний проект Gray Matter при участии/контроле id.

    На E3 реакция оказалась очень тёплой; GameSpot включала показ игры в число сильных проектов выставки. Carmack прямо перечислил реакцию на Wolfenstein как один из факторов, заставивших команду пересмотреть собственное направление. GameSpot +1

    Получается важный психологический эффект:

    OLD IP

    не обязательно означает:

    OLD GAME

    Можно взять:

    Wolfenstein 1992

    и через восемь лет превратить его в:

    современную полноценную 3D game

    Не копируя оригинал буквально.

    И возникает очевидный вопрос

    Если с Wolfenstein это работает:

    А ЧТО МОЖНО СДЕЛАТЬ С DOOM НА TECHNOLOGY 2000-х?

    Вот это уже очень сильная идея.

    Потому что Doom для id — гораздо больше Wolfenstein.

    Это игра, на которой:

    компания стала мировой;

    deathmatch стал массовым;

    моддинг взорвался;

    сама идентичность id окончательно сформировалась.

    С современным renderer Doom можно было не продолжить, а фактически переосмыслить заново.

    И третий фактор — новая rendering technology Carmack

    Вот здесь технологическая id окончательно соединяется с проектным решением.

    Carmack прямо назвал одной из причин:

    excitement about what we can do with the latest rendering technology. GitHub

    То есть выбор Doom был не только:

    любим старую игру

    А:

    У МЕНЯ ЕСТЬ НОВЫЙ TECHNOLOGICAL DIRECTION

    И

    DOOM МОЖЕТ БЫТЬ ИДЕАЛЬНОЙ ИГРОЙ ДЛЯ НЕГО

    Это абсолютная квинтэссенция post-Romero id.

    Правда, важная хронологическая поправка

    Нельзя сказать:

    в июне 2000

    Carmack уже имел готовый Doom 3 renderer с окончательной системой unified per-pixel lighting и stencil shadows

    ↓

    поэтому выбрал Doom

    Это слишком аккуратная история.

    В момент ультиматума Carmack уже активно исследовал новое поколение graphics technology, но одна из главных архитектурных идей будущего Doom 3 — единая система dynamic lighting/shadowing — окончательно кристаллизовалась после greenlight, в ходе дальнейшего R&D.

    Wired описывает, как осенью 2000-го Carmack глубоко погрузился в проблему realtime lighting, из которой затем вырастет определяющая визуальная технология Doom 3. WIRED

    То есть точнее:

    июнь 2000

    Carmack знает: следующая graphics generation будет очень большой

    ↓

    DOOM кажется идеальным canvas

    ↓

    после решения

    renderer research ещё сильнее формирует, КАКИМ Doom будет И Doom действительно идеально подходит для lighting revolution

    Почему?

    Потому что Doom по самой своей исходной ДНК построена вокруг:

    LIGHT

    DARKNESS

    SURPRISE

    MONSTER

    Оригинальный Doom уже в 1993 году использовал:

    мигающие lights;

    тёмные areas;

    sudden reveals;

    силуэты;

    изменение освещения как часть атмосферы.

    Но всё это было очень примитивно технически.

    Новый renderer потенциально позволял:

    реальный moving light

    ↓

    реальный moving shadow

    ↓

    monster выходит из darkness

    ↓

    свет реагирует на moving geometry

    То есть технология могла усиливать не только картинку, а сам horror-language Doom.

    И именно в Doom 3 Carmack позже сформулирует проблему старой графики как Hanna-Barbera effect

    До нового engine:

    static world освещается одним способом

    dynamic object другим

    ↓

    движущийся объект визуально иногда «торчит» из сцены

    Как в старом мультфильме:

    видишь камень

    и заранее понимаешь: ЭТОТ КАМЕНЬ СЕЙЧАС УПАДЁТ

    потому что нарисован иначе

    Carmack хотел унифицировать lighting:

    STATIC OBJECT

    DYNAMIC OBJECT

    STATIC LIGHT

    DYNAMIC LIGHT

    ↓

    ОДНИ И ТЕ ЖЕ LIGHTING RULES

    Позднее он называл это фундаментальной целью Doom 3 renderer. Fabien Sanglard

    И для хоррора эта идея практически идеальна:

    если ты больше не можешь визуально отличить «декорацию» от активного объекта, мир становится намного менее предсказуемым.

    Но весной 2000 года ownership всё ещё говорит «нет»

    И вот здесь надо понимать юридическую структуру.

    Carmack пишет:

    Kevin + Adrian

    control >50% of the company

    GitHub

    То есть формально:

    John Carmack НЕ МОЖЕТ просто сказать:

    «я решил, делаем Doom»

    Компания ему не принадлежит единолично.

    Kevin Cloud и Adrian Carmack вместе обладают достаточной долей, чтобы заблокировать решение.

    И они это неоднократно делали.

    Вот здесь возникает парадокс зрелой id

    Мы в пункте 33 говорили:

    post-Romero id

    = Carmack-driven technology company

    Но юридически:

    Carmack ≠ мажоритарный диктатор

    Есть:

    OWNERSHIP POWER

    и есть:

    FUNCTIONAL POWER

    И эти две системы сталкиваются.

    Ownership power

    Kevin + Adrian:

    50%

    Могут сказать:

    NO DOOM Functional power

    Carmack:

    principal engine architect

    technical direction

    public technology figure

    основа licensing prestige

    человек, вокруг следующего renderer строится production

    А рядом с ним часть сотрудников, которые тоже хотят Doom.

    И Carmack фактически говорит владельцам:

    можете юридически заблокировать Doom

    НО

    тогда вам придётся сохранить компанию БЕЗ НАС

    Вот настоящий смысл ультиматума.

    Это не обычное «я увольняюсь»

    Формулировка Carmack:

    “We are working on DOOM for the next project unless you fire us.” GitHub +1

    Обратите внимание на:

    WE

    Не:

    I

    То есть Carmack заранее поговорил с частью команды и организовал фактически внутренний блок.

    Его собственные слова:

    они решили, что вопрос достаточно важен, чтобы протащить компанию через неприятную драку. GitHub

    Это буквально корпоративный мятеж.

    И здесь technology leader превращается в политическую силу

    До этого власть Carmack часто была:

    feature нужен?

    ↓

    Carmack должен его написать

    ↓

    значит Carmack имеет veto

    Теперь:

    КАКУЮ ИГРУ ДЕЛАЕТ ВСЯ КОМПАНИЯ?

    ↓

    Carmack использует:

    свою незаменимость

    Doom 3 — один из самых интересных случаев во всей истории id, потому что здесь два главных принципа компании одновременно идеально совпали и начали мешать друг другу.

    Первый принцип:

    новая technology должна менять саму игру

    Второй:

    новая DOOM должна ощущаться как DOOM

    И id действительно нашла почти идеальное применение новой технологии Carmack:

    dynamic lighting + real-time shadows + normal mapping + specular materials

    ↓

    DARKNESS + MONSTERS + HORROR

    Проблема в том, что, усиливая одну часть исторической ДНК Doom — страх перед тем, что находится за следующим углом, — Doom 3 сильно ослабила другую:

    скорость + агрессия + толпы enemies + combat flow + пространственная свобода

    Поэтому Doom 3 получилась не просто:

    DOOM с новой графикой

    А:

    интерпретацией того, что именно в Doom является самым важным.

    И именно вокруг этой интерпретации серия потом будет спорить десятилетиями.

    Сначала важная терминологическая поправка: в 2004 это ещё не называли id Tech 4

    Сегодня движок Doom 3 принято называть:

    id Tech 4

    Но единая нумерация id Tech появилась позже, в эпоху id Tech 5; старые поколения были ретроспективно переименованы.

    В 2000–2004 обычно говорили просто:

    DOOM 3 ENGINE

    или:

    new Doom technology

    По современной номенклатуре это и есть id Tech 4. PC Gamer +1

    И технически скачок действительно был огромный.

    Главная идея Carmack: свет больше не должен быть декорацией

    Quake III в основном использовала:

    STATIC LIGHTMAPS

    Уровень заранее компилируется.

    Свет и тени в значительной мере:

    BAKED

    То есть художник может создать красивое освещение, но world не рассчитывает его полноценным образом заново каждую frame.

    Doom 3 строится вокруг совершенно другой философии.

    Carmack формулировал её:

    “lights are first class citizens.”

    То есть свет становится почти таким же полноценным объектом мира, как model или entity. GameSpot

    Грубо:

    LIGHT

    теперь не:

    информация, запечённая в стену

    а:

    ОБЪЕКТ, который реально освещает сцену Следовательно, moving light может породить moving shadow

    Например:

    лампа ↓ вращающийся вентилятор ↓ персонаж

    Движется вентилятор —

    его тень движется по стене и по персонажу

    И это происходит runtime.

    В 2001 GameSpot описывала новый renderer именно через этот разрыв с Quake III: вместо преимущественно предварительно рассчитанного освещения Doom 3 выполняет гораздо больше lighting в реальном времени, причём одинаковая lighting model используется для объектов мира. GameSpot

    Сегодня:

    ну да, тень двигается

    В 2001:

    ЕБАТЬ И Carmack специально хотел избавиться от «эффекта Hanna-Barbera»

    Его аналогия очень хорошая.

    вот этот камень СЕЙЧАС покатится

    это world

    А normal mapping позволяет сделать grotesque Doom почти физическим

    Вот здесь важная техническая поправка.

    Quake Wars действительно использовала логически единую текстуру размером примерно:

    32 000 × 32 000

    для terrain. Carmack сам называл именно такой размер. Fabien Sanglard

    Но схема, конечно, не:

    32K × 32K image

    ↓

    LOAD ALL INTO VRAM

    ↓

    GOOD LUCK

    Потому что:

    32 000 × 32 000 ≈ миллиард texels

    а с несколькими channels и mip-levels это уже гигантский объём данных.

    Вместо этого renderer создаёт иллюзию, будто GPU умеет работать с настолько огромной texture непосредственно.

    Carmack описывал систему как управление отдельными texture blocks плюс fragment-program logic, которое позволяет приложению обращаться с terrain как с единым огромным texture space. Его более поздняя generalized версия уже прямо называлась paged virtual texturing. Fabien Sanglard +1

    По сути:

    VIRTUAL TEXTURE

    32K × 32K

    ↓

    делится на:

    маленькие BLOCKS / PAGES

    ↓

    в runtime нужны только:

    те blocks и те уровни detail, которые актуальны для текущего кадра

    ↓

    они присутствуют в рабочей памяти / GPU cache

    ↓

    для shader'а всё выглядит так, будто существует огромная непрерывная texture

    Это очень похоже по философии на:

    VIRTUAL MEMORY

    для обычной RAM.

    Программа думает:

    у меня огромное address space

    а операционная система:

    физически подкладывает только нужные pages
